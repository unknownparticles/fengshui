# Spec Delta

## Purpose

保证现场堪舆应用能以纯静态资源部署在 GitHub Pages 项目路径或根路径，保持页面路由、安装入口、离线缓存和更新的正确性，并让发布和回滚具有可核实的验证记录。

## ADDED Requirements

### Requirement: 静态托管独立运行

应用 MUST 在 HTTPS 静态托管下独立运行，不需要服务器进程、服务端 API、数据库服务或运行期私密密钥；构建产物不得包含密钥与真实现场项目数据。网站 SHALL 说明现场数据本地处理以及托管方可能记录普通访问日志。

#### Scenario: 部署目录只有静态资源
- **WHEN** 用户通过 HTTPS 打开部署后的构建产物
- **THEN** 可完成核心工作流，无需启动后端或配置密钥

### Requirement: 项目子路径与根路径一致适配

系统 MUST 支持部署到 `/<repo>/` 及 `/`，所有资源、manifest 的 id／start_url／scope 和 SW 注册地址／控制范围随基路径变化。项目 SW MUST 不控制同源其他项目路径，清理缓存限定在本应用命名空间。

#### Scenario: 仓库子路径安装和离线启动
- **WHEN** 应用部署到 `/fengshui/` 并安装后离线打开
- **THEN** 页面、资源和 SW 均在 `/fengshui/` 范围内解析，未请求错误的根路径资源

#### Scenario: 根路径部署
- **WHEN** 构建基路径为 `/`
- **THEN** 安装入口与核心资源在根路径正确加载，无残留 `/fengshui/` 前缀

### Requirement: 刷新与分享页面不依赖服务端重写

系统 SHALL 使用可在静态主机直接解析的路由方式；刷新、直接进入资料页和浏览器前进后退 MUST 保持可用。项目敏感信息不得写入 URL，包含本地项目标识的链接在另一设备上 SHALL 提示项目不存在而不产生伪数据。

#### Scenario: 刷新资料深层页面
- **WHEN** 用户直接访问或刷新 `/fengshui/#/knowledge/zi`
- **THEN** 主机返回应用入口并显示对应资料，不出现服务端路由 404

### Requirement: 发布与回滚可审计

正式发布 MUST 在规格校验、类型／构建检查、关键计算与本地数据测试以及部署路径检查通过后进行；PR 验证不得执行正式发布。发布 SHALL 有版本和提交对应记录；回滚旧代码必须保持新版本数据可安全识别，遇到不支持的数据版本进入只读与导出流程，不清空数据。

#### Scenario: 验证失败阻止发布
- **WHEN** 任一必需验证失败
- **THEN** 发布任务不执行，已发布版本继续可用

#### Scenario: 旧应用读取新数据
- **WHEN** 回滚后旧应用发现不支持的数据库版本
- **THEN** 应用显示版本不兼容，允许只读查看可理解的数据及原始备份导出，不重新初始化覆盖数据库
